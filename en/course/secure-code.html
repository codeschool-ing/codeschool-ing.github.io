Secure Coding

Most flaws are not broken into: they are written in. Learn to code so the attack has no way in.

  • 60 hours
  • Level: intermediate

What you need first

Requires attacks and threats, and a language of your own to write the flaw in.

What you will learn

  • Why most flaws are born in the code
  • Input validation and output handling
  • Preventing SQL and command injection
  • Preventing XSS, CSRF and session flaws
  • Secrets, dependencies and third-party code
  • Code review with a security eye

Full topic list

  • Where the flaw is born: requirement, design or implementation
  • Never trust input: allowlist validation
  • Client-side and server-side validation: why you need both
  • Output handling: escaping by context (HTML, attribute, JavaScript, URL)
  • Preventing SQL injection: parameterised queries and using an ORM correctly
  • Command, LDAP and template injection
  • Preventing XSS: reflected, stored and DOM-based
  • Content Security Policy as a second line of defence
  • CSRF: tokens, the SameSite attribute and origin checks
  • Sessions: generation, expiry, rotation and invalidation
  • Passwords: bcrypt, Argon2 and a policy users can actually follow
  • Access control in code: always check on the server
  • Insecure direct object reference (IDOR)
  • Insecure deserialisation and file upload
  • Error messages and logs: what must never leak
  • Secrets: environment variables, vaults and what never goes in the repository
  • Dependencies: known vulnerabilities, updates and version pinning
  • Code review with a security eye: what to look for first
  • Automated security testing inside the project
  • OWASP ASVS and the Cheat Sheets in daily use
