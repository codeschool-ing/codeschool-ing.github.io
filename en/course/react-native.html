Mobile Apps with React Native

One codebase, two stores: React Native and Expo with the JavaScript you already write — and an honest account of what the bridge costs and when you have to open the native project.

  • 90 hours
  • Level: intermediate

What you need first

Requires JavaScript, React included — the components, the hooks and the state are the same ideas. No native experience assumed.

What you will learn

  • React Native and Expo: the project, the runtime and the tooling
  • Components, styling and layout with Flexbox
  • Navigation, state and data from an API
  • Device features: camera, storage, location and notifications
  • Native modules, for when the library does not exist
  • Builds, over-the-air updates and both stores

Full topic list

  • How React Native runs: JavaScript, the new architecture and the native side
  • Expo against bare React Native: what you gain and what you give up
  • The project, Metro, the development build and the simulator
  • Core components: View, Text, Image, ScrollView — the ones that are not HTML
  • Styling: StyleSheet, Flexbox, and the CSS that does not exist here
  • Platform differences: Platform.select, and the file ending in .ios.js
  • Lists: FlatList, SectionList, keys and virtualisation
  • React Navigation: stack, tabs, params and deep links
  • State: hooks, context, and a store for when context is not enough
  • Fetching, caching and offline with TanStack Query
  • Forms, validation and a keyboard that covers the field
  • Animation: Reanimated, gestures, and 60fps off the JavaScript thread
  • Camera, image picker, files and permissions
  • Storage: AsyncStorage, MMKV, SQLite and the secure store
  • Location, maps and position in the background
  • Push notifications, with Expo and with Firebase
  • Native modules: calling Kotlin and Swift from JavaScript
  • Debugging: DevTools, logs, and the bug that only happens in release
  • Performance: re-renders, list jank, image memory and bundle size
  • EAS Build: credentials, and building without a Mac in the room
  • Over-the-air updates: what may be shipped that way, and what may not
  • A look at Flutter and Kotlin Multiplatform: the other multiplatform routes
