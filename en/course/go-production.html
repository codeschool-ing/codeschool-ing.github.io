Course

Go in Production: CLIs, Tooling and Performance

The tooling that makes Go the language of infrastructure: command line, profiling, cross-compilation and the advanced corners.

  • 70 hours
  • Level: advanced

What you need first

Requires concurrency and some project experience: this is the most advanced course on the track.

What you will learn

  • Command-line programs with Cobra and bubbletea
  • The full toolchain: build, vet, linters and security analysis
  • Profiling with pprof and trace: finding the real bottleneck
  • Cross-compilation and binary distribution
  • Code generation, build tags and reflection
  • The advanced corners: escape analysis, `unsafe` and CGO

Full topic list

  • A command-line program: arguments, subcommands and output
  • Cobra: commands, flags, help and autocompletion
  • urfave/cli as a lighter alternative
  • bubbletea: an interactive terminal interface
  • Everyday commands: `go run`, `build`, `install`, `test`, `doc`
  • `go fmt` and `goimports`: formatting that ends the argument
  • `go vet`: what it catches before the tests do
  • Linters: revive, staticcheck and golangci-lint in the pipeline
  • `govulncheck`: known vulnerabilities in the dependency tree
  • `go generate`: code generation as part of the build
  • Build tags and constraints by file, operating system and architecture
  • pprof: CPU, memory, blocking and goroutines
  • Reading a profile: the most expensive call versus the most frequent one
  • `trace`: actually seeing the scheduler and the latency
  • The race detector in the continuous integration pipeline
  • Cross-compilation: `GOOS`, `GOARCH` and a binary for another machine
  • Shrinking the binary: compiler and linker flags
  • Distributing: minimal container, `distroless` and signing
  • Memory management in depth: stack, heap and the collector
  • Escape analysis: why that variable ended up on the heap
  • Reflection (`reflect`): power, cost and when not to use it
  • The `unsafe` package: what it allows and what it costs
  • CGO: calling C from Go and what you give up by doing so
  • Plugins and dynamic loading: the real limits of the approach
